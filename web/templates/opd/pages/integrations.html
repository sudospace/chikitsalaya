SMS (used for online-booking OTP)

Only one real mechanism is supported today: a generic webhook — point it at any HTTP endpoint that accepts a JSON body of {"to": "...", "message": "..."} (your own relay, or a gateway that offers a plain webhook). Leave inactive to keep using dev-mode, which just logs the code to the server console instead of sending it.

Email

No feature in the app sends email yet — this stores SMTP credentials for when one does (e.g. appointment confirmations).

Payment

No billing/payment-collection flow exists in the app yet (consultation fees are just captured as an amount + paid/unpaid flag) — this only stores gateway credentials for whenever that's built.

Storage (patient documents)

Where uploaded patient report files physically live. Local storage is encrypted at rest and fully working today; Google Drive and S3 are configurable here but not yet wired up — picking either will save your settings, but uploads will fail until that backend is implemented.

The encryption key is set via the CHIKITSALAYA_LOCAL_STORAGE_KEY environment variable on the server, not here — nothing to configure on this page for local storage.
